# Arcont v0.1 — CC0 Staging Disposition

Status: PRESERVED / NOT MERGED WHOLESALE
Source branch: `assets/cc0-staging`
Target integration branch: `integration/arcont-v0.1`

## Decision

`assets/cc0-staging` remains a source-ingest/archive branch and is intentionally not merged wholesale into the playable integration line.

The branch has 14 commits that are not ancestors of the current art/integration line. Those commits primarily represent ingest/source-library work, including the later CC0 forest-library and Poly Haven terrain-PBR ingest pipeline. Equivalent selected runtime assets and promotion machinery already exist in the playable art lineage, so commit-count uniqueness alone is not a reason to import every vendor/source file.

## Why not merge it wholesale

A wholesale merge would reintroduce large vendor trees, alternate formats, previews and source-pack material into the playable history without proving runtime need. This would increase repository weight and blur the distinction between:

- source archive;
- audited candidate;
- promoted runtime asset.

## Required classification for any staging-only content

Before anything is copied from staging into integration, it must satisfy all of:

1. The runtime branch does not already contain an equivalent or better promoted asset.
2. Source/license provenance is present and valid.
3. Exact selected file is identified; entire packs are not promoted by default.
4. Scale/orientation/material import is audited.
5. The asset has a concrete semantic gameplay/art role.
6. Android cost and visual fit are acceptable for its intended repetition count.
7. Promotion destination and fallback behavior are documented.

## Known staging-only families worth preserving for later audit

- later CC0 forest-library ingest/source material;
- Poly Haven terrain-PBR ingest/source records;
- source manifests/licenses/workflow refinements associated with those ingests.

These remain valuable as provenance and source recovery even when their selected runtime derivatives already exist elsewhere.

## Branch lifecycle

Do not delete `assets/cc0-staging` during v0.1 consolidation. Freeze it as an ingest/archive source. After v0.1 reaches `main`, perform a separate repository-size/LFS/archive review before deciding whether source packs should remain in Git history, move to Git LFS, move to release/archive storage, or be regenerated by pinned ingest workflows.

## Current disposition

- Merge into integration: NO.
- Delete branch: NO.
- Promote missing assets selectively: YES, only after audit.
- Treat staging as runtime truth: NO.
